Darwinbox

Forty five months on an enterprise HRMS used by clients across APAC, MENA, Europe and North America. I joined as a Product Analyst and left as a Senior one, having mentored three juniors and picked up an Exemplary Contributor award along the way.

The document is the job

A spec that works answers the question before anyone has to ask it. Mine carried the edge cases and the test notes, so the answer sat in the document instead of in a call three weeks later. I also tracked which developer would pick up which spec next sprint and ran the handover before anyone was blocked. Across 45 months that came to more than 200 engineering-ready documents, covering the employee lifecycle, org structure, access controls and bulk data. Features released this way landed between 5 and 60 percent account-level adoption in the quarters after launch. I benchmarked what we were building against the top five HRMS platforms on the Gartner Magic Quadrant, so parity was an input to the design rather than a gap someone found later.

Nobody was looking at the data we already paid for

Pendo was already bought and barely used. Two or three people ran in-app surveys on it and nobody touched the analytics. I dug in out of curiosity and found it could show what people actually did: click paths, funnel drop-offs, how often a feature got touched. So I built the usage-analytics function from nothing. The first thing it told us was uncomfortable. Several genuinely good features were barely being used, because they were buried, or the setting had a name that meant nothing to the person reading it. Nobody reads release notes, so the product has to explain itself. I rewrote configuration names in plain language, added help text, moved settings to where people would look, then used Pendo to prove usage climbed. I contributed to the dashboard revamp that reached over 322,000 enterprise users, where time spent on key actions fell 45 percent.

Translated by people who did not speak the language

Every new string was hard-coded, then translated by pasting it into ChatGPT. The developers doing the pasting did not speak the language. Clients who did kept flagging translations that were technically correct and meaningless in context. Leadership believed this was already solved, because a tech architect had shipped a central page for editing translations. It was not solved. The URL was per-client and hidden with no clear owner, strings sat in different files per module across a mixed PHP and Angular codebase, and finding the broken one was painful. I went looking myself, wrote up what was actually wrong, and it became a roadmap item I owned the PRD for. The product now runs in more than 50 languages without engineering in the loop.

Where enterprise data actually enters the system

Bulk import is where enterprise HR data actually enters the system, and it was where admins failed most often. A failed import does not stay failed quietly: either support cleans it up or the client does. I redesigned it around validation, format handling and field-level guidance so the first attempt succeeded. I also specified a conversational import assistant, where an admin describes what they want in plain language and the system generates the file, catches the errors and routes the approvals. It was specified in full and never built.

The trust layer for the agent economy

Software is starting to spend money on our behalf. These four protocols, built in order, cover the steps that have to hold when it does.

01

Realium, settlement

A contractor finishes verified work on day zero and then waits out the payment cycle. Realium turns that site-verified progress into a receivable a bank will actually lend against, so sixty percent reaches the contractor on day one instead of day 148, against an Ed25519 attestation signed on site. It placed top 3 at the ReEnvision 5.0 conclave, judged by senior technology leaders. See the demo or the source.

02

Heirloom, memory

A firm loses context when a partner leaves, and loses it again when it switches vendors. Heirloom keeps that memory with the firm instead: queries scoped by role-based cryptography, and a schema that is portable and model independent. See the demo or the source.

03

Turnstile, commerce

Bot defences were built for a web where every visitor was a person. Turnstile tells human sessions apart from AI agents, which lets it recover the checkouts those defences decline by mistake, and serve agents a machine-readable storefront instead of a page they have to guess at. See the demo or the source.

04

Windtunnel, simulation

You usually learn a pricing change was wrong from the customers who leave over it. Windtunnel builds synthetic cohorts out of real support and transaction history and runs the change thousands of times first, so the breakage shows up before anyone real is affected. See the demo or the source.
